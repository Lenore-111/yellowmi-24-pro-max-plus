# 设置遮挡、密钥输入与生图反馈验收（2026-10-12）

基于 Yellow Mi `f55ad9edbf4944439c8bbd1ccd3dff1dd135fb4b`，修复用户实际反馈的三个界面问题。

## 复现与处理

- 设置页：在 390×640 的真实酒馆页面，设备列表仅剩 18px 高，其内容高 1117px；配图和主屏幕区域留在滚动区之外，电池条目被挤压。现将资料卡、玩法、设备列表、配图与主屏幕放在一个滚动区域，保留固定标题和底部手势空间。样式地址更新为新的构建标识，避免旧样式缓存。
- 密钥栏：原来使用密码输入和密码自动填充提示。针对手机键盘的粘贴困难，改成普通文本输入加视觉遮蔽，并关闭自动填充；提供「显示密钥／隐藏密钥」。不支持文字遮蔽的浏览器默认保留密码框，主动点击「显示密钥」仍可切换到普通输入。浏览器拒绝读取剪贴板时，聚焦输入框，提示放在密钥栏旁边。剪贴板只在点击按钮时读取，原有异步失效保护和保存流程保持有效。
- 生图反馈：在深滚动动态点击生成，实际请求发出并收到受控 502，但原提示位于可视区上方一万余像素，用户看不到。现将配图等待、取消、成功和错误放在标题下的独立区域；不随动态滚出视口，不把浏览位置强制拉到顶部。

文字遮蔽依据 [浏览器属性说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/-webkit-text-security)，实现带有功能检测及普通明文输入开关。网页无法强制打开手机系统剪贴板面板。

## 验证

`node --import ./scripts/test-host-register.mjs --test tests/*.test.mjs`：61/61 通过。两项新增回归验证普通输入的遮蔽和显示、拒绝读取时的就近提示、迟到剪贴板不覆盖新输入或新页面、不支持遮蔽时的后备输入，以及深滚动配图等待／错误位于滚动区外、失败保留原图与浏览位置。相关模块语法检查、`git diff --check` 通过。

实际安装本次模块到官方 SillyTavern 1.18.0（`51ad27fb86d39a3daca3adaa970375c9670c12df`）及 1.12.0（`53496d70f1cfca7891d75058e8be39999ea67657`）。Chromium 153 / Playwright 保留浏览器跨域检查，在 320×640、390×640、390×844、820×1180、1440×1000 五个视口分别操作。

每套宿主、每个视口完成以下四组，共 40 组检查通过；页面脚本异常为零：

1. 设置页统一滚动，检查电池、系统、设备刷新、主屏幕和配图按钮的中心点击位置不被遮挡；实际切换充电、恢复桌面并打开配图设置。
2. 密钥采用普通输入，默认遮蔽；原生剪贴板通过输入框粘贴，显示／隐藏切换正常；受控拒绝读取时，焦点返回密钥栏并出现就近提示。
3. 填写自有测试密钥、模型并保存，通过酒馆代理发出 `/ai/generate-image` 请求；核对密钥匹配、模型、单张和 28 步。深滚动点击生成后，等待与成功状态可见，返回的压缩包图片实际解码显示。
4. 重绘返回受控 502，错误状态位于可视范围内，原图路径不变。
